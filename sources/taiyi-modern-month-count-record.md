# 现代 production 月计积数

## 永久规则标识

- `MODERN-TAIYI-MONTH-COUNT`
- runtime: `kintaiyi.taiyi_modern_month_count`

## 来源骨架

《太乙统宗宝鉴》卷一“求天正积月术”：

> 所求积年内减一算，以十二乘之，为所求岁前天正十一月之积月。

《太乙金镜式经》卷一“推六纪月建法”：

> 三十年有三百六十个月……
> 若有闰月，只以逐月节气时刻为正也。

项目production把两条组合为：

1. 太乙积年仍提供连续“年块”编号；
2. 每个年块固定12个太阳月；
3. 十二节的真实交节瞬间决定当前月建；
4. 农历闰月不额外多算一个太乙月。

## 月序

以天正十一月/子月为第1：

1. 子
2. 丑
3. 寅
4. 卯
5. 辰
6. 巳
7. 午
8. 未
9. 申
10. 酉
11. 戌
12. 亥

因此：

`accumulated_month = (accumulated_year - 1) * 12 + month_index`

## 月计循环年

一个12太阳月块：

`大雪(子) -> ... -> 立冬(亥)`

因此公历Y年的大雪开始：

> 月计循环年 Y+1 的第1月（子月）。

例如：

- 2026大雪 -> cycle_historical_year=2027, 子月；
- 2027小寒 -> 同一cycle year的丑月；
- …
- 2027立冬 -> 同一cycle year的亥月。

## 与冬至换岁分离

冬至发生在子月内部。

所以：

- 大雪：月计推进到新子月；
- 冬至：岁计换年；
- 冬至本身不再次推进月计。

这是两个不同层的边界。

## 与春节/闰月分离

春节只改变现代农历年/月事实，不改变太乙太阳月。

闰月同样不额外推进月计。

例如2025-07-25现代农历进入闰六月，但仍在小暑->立秋的未月内，月计积数不变。

## production 结果

`modern_month_count(datetime)` 已直接接入：

`accumulated_month -> 月计阳局 -> G2..G7`

所以月计现在不再要求调用方手工提供古法积月常数。


## 字段命名防混淆

为了避免把月计12月块误认成太乙岁：

- `month_formula_year`：只服务积月公式；
- `cycle_historical_year`：兼容旧字段，语义同上；
- `taiyi_year`：只能来自真实冬至岁界，不由月计模块生成。

因此在公历Y年“大雪后、冬至前”允许同时出现：

- 月建 = 子；
- `month_formula_year = Y+1`；
- `taiyi_year = Y`。

到冬至精确瞬间：

- 月建仍为子；
- `month_formula_year`不变；
- `taiyi_year`才切换为`Y+1`。

这不是冲突，而是“月界”和“岁界”本来就是两个独立边界。
