# C70 J4M-11 风云飞鸟观测事件语法审计

日期：2026-10-05

## 目标

继续执行“原文说到哪里，runtime 只做到哪里”的规则，对 J4M-11《太乙金镜式经》卷四“推太乙风云飞鸟助战法”进行输入语义审计。

本条本质上依赖外部观测，不允许由盘内字段或抽象动作词伪造自然现象。

## 一、每条事件必须显式说明现象类型

旧 runtime 允许：

- phenomenon 缺失
- 但 action=扶、target=主人阵

仍可触发“扶主人阵 -> 主胜”。

这使“动作词”脱离风、云、飞鸟观测也能生成古籍断语，超过原文范围。

C70 固定：

每条事件的 phenomenon 必须明确属于：

- 风
- 云
- 飞鸟
- 风云
- 风云飞鸟

缺失 phenomenon 与未知自然现象一律 unmatched，不产生胜负。

## 二、“迫击”不自动扩成“冲击”

《金镜》本条写：

“迫击大将宫者主败。”

旧 runtime 为方便输入，把：

- 迫击
- 冲击

都当成同一事件。

但“冲击”在本条其他句位有自己的文字环境，不能因为现代语义接近就自动视为“迫击大将宫”。

C70 删除该近义扩张：

- action=迫击 + target=大将宫 -> 按《金镜》本句，主败；
- action=冲击 + target=大将宫 -> 正文未覆盖该组合，不判。

## 三、与《景祐太乙福应经》继续分离

《福应经》卷四另有：

- 迫击客大将宫 -> 客败
- 迫击主将宫 -> 主败
- 从主人刑上来 -> 主人败
- 从客刑上来 -> 客败

这些已经进入独立 JF4M profile，不用于补写 J4M runtime。

因此 J4M-11 继续逐字服从当前《金镜》四库本文本，即便其他古本更展开。

## 四、众来噪阵

“众来噪阵”继续：

- 可记录观测；
- 不单独产生 winner/loser。

原因是《金镜》该句句读不能可靠支持“噪阵”自身的独立胜负结论；《福应经》则把鸟噪与风云冲阵组合叙述，更说明不应从单独噪声制造结果。

## 五、修改

- src/kintaiyi/jinjing_v4_military.py
  - phenomenon 由“可省略”改为“必须显式”
  - 大将宫仅接受 action=迫击，不接受自动近义“冲击”
- rules/jinjing_v4_military.json
  - 新增 source_event_schema_audited_strict_wording
  - 新增 canonical_constraints
- tests/test_jinjing_v4_military.py
  - 缺 phenomenon 不得触发
  - 冲击大将宫不得等同迫击
  - 迫击大将宫仍按原文生效
- tests/test_jinjing_v4_military_record.py
  - 锁定来源语义边界

## 固定原则

J4M-11 不做：

- 天气 API 自动生成古代风云飞鸟事件；
- 盘内飞鸟位置伪造成外部观测；
- 缺少 phenomenon 只靠动作词判断；
- 现代近义词自动归一成古籍动作；
- 从 JF4M 挑更完整条文补 J4M。
