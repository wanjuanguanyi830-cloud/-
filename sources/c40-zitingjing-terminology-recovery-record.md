# C40 紫庭旧术语库恢复骨架

日期：2026-10-05

## 背景

用户确认：

- 此前已经提供过《太乙紫庭祕訣》研易楼藏明钞本扫描文件；
- 该扫描内容已经在本地术语主库做过初步整理；
- 当前 GitHub 仓库尚未迁移本地 `terminology.json`。

因此 C40 的目标不是重新 OCR / 重建一套术语，而是建立**恢复映射骨架**，等待旧术语库或扫描本重新可取后回填。

## 新增

`terminology/zitingjing-migration-map.json`

该文件只保存：

- 已知核心词条；
- 别名/异写；
- 当前 rule key；
- 当前 source 状态；
- 需要从旧术语库恢复的字段；
- 当前不能自动确定的明钞字形、页码。

## 六个核心迁移项

1. 太乙九星 → `taiyi_nine_stars`
2. 文昌九星 → `wenchang_nine_stars`
3. 文昌变化 → `wenchang_changes`
4. 始击变化 → `shiji_changes`
5. 三旗行宫 → `three_banners`
6. 九宫贵神 → `nine_palace_nobles`

## 恢复优先级

优先恢复：

1. 文昌九星
2. 三旗行宫
3. 九宫贵神

理由：

- 这三项仍存在紫庭正文/归属缺口；
- 旧术语库可能已经保存扫描页、原字形或术名索引；
- 恢复后可直接帮助 C20/C34 的来源校勘。

随后核对：

4. 太乙九星
5. 文昌变化
6. 始击变化

后三项当前已有结构化规则，主要用于补：

- 明钞本页码；
- 原字形；
- 旧术语 ID；
- 旧定义 / 旧备注；
- 异文记录。

## 强制留空字段

在旧术语库或扫描页未恢复前：

- `manuscript_form = null`
- `source_page = null`

不得用：

- 《三才世纬》
- 《太乙统宗宝鉴》
- 现代整理材料
- OCR 推测

代填研易楼明钞本的实际字形或页码。

## 文昌九星异文组

外部参校目前至少见：

- 明雄 / 明维 / 明維
- 阴玄 / 陰玄 / 阴德 / 陰德
- 招摇 / 招搖 / 招煥
- 华明 / 華明
- 雄明 / 维明 / 維明

这些只作为**旧术语命中候选**。

在恢复研易楼本实际词形之前：

`canonical manuscript form = unresolved`

## 三旗 / 九宫贵神

旧术语库中即使存在相关词条，也不能单凭“词条存在”证明：

- 它们一定出自研易楼明钞本；
- 它们一定属于《太乙紫庭秘诀》正文；
- 它们可以升级为紫庭 canonical。

必须同时恢复：

- source page
- source section
- manuscript form

才能升级来源证据。

## 当前不实现旧术语解析器

目前不知道旧本地 `terminology.json` 的完整 schema，因此 C40 不写自动 parser。

这样避免：

- 猜字段名；
- 猜 ID 结构；
- 错把旧别名当主词条；
- 丢失旧备注或页码。

待旧文件重新提供后，再按真实 schema 写一次性 migration adapter。
