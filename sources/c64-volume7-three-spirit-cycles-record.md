# C64 卷七天乙 / 地乙 / 直符三神 360/36 行宫基础层

日期：2026-10-05

## 1. 范围

C64 实现《太乙统宗宝鉴》卷七三项：

- 天乙太乙金神；
- 地乙太乙土神；
- 直符太乙火神。

本批只实现三神的：

- 大周 / 小周；
- 十二宫行序；
- 起宫；
- 每宫停留年数；
- 所在宫；
- 入宫第几年。

唯一 runtime：

`src/kintaiyi/state_spirit_cycles.py`

rule ids：

- `C64-TIANYI`
- `C64-DIYI`
- `C64-ZHIFU`

同宫灾应另层，不在 C64 自动触发。

## 2. 卷七共同算法

三条直接正文共同见：

- 大周 360；
- 小周 36；
- 行宫率 3；
- 每宫 3 年；
- 九宫之后接绛宫、明堂、玉堂。

因此十二宫固定为：

`1 → 2 → 3 → 4 → 5 → 6 → 7 → 8 → 9 → 绛宫 → 明堂 → 玉堂`

36 年正好：

`12宫 × 每宫3年`

余 0 保留为第 36 年 / 本轮最后一宫，不产生第 0 年。

## 3. 天乙金神

卷七直接正文：

- 金神；
- 大周 360；
- 小周 36；
- 命起六宫；
- 顺行十二宫。

C64 路线：

`6 → 7 → 8 → 9 → 绛宫 → 明堂 → 玉堂 → 1 → 2 → 3 → 4 → 5`

每一项停 3 年。

后期参校另明确：

- 上元甲子起 6；
- 中元起 2；
- 下元起绛宫。

这与 C64 连续 12 宫、3 年一移的计算一致。

## 4. 地乙土神

卷七直接正文：

- 土神；
- 大周 360；
- 小周 36；
- 命起九宫；
- 继绛宫、明堂、玉堂，再接一宫顺行。

C64 路线：

`9 → 绛宫 → 明堂 → 玉堂 → 1 → 2 → 3 → 4 → 5 → 6 → 7 → 8`

后期参校：

- 上元 9；
- 中元 5；
- 下元 1。

与连续周期一致。

## 5. 直符火神

卷七直接正文：

- 大周 360；
- 小周 36；
- 命起五宫；
- 顺行九宫后接绛、明、玉。

C64 路线：

`5 → 6 → 7 → 8 → 9 → 绛宫 → 明堂 → 玉堂 → 1 → 2 → 3 → 4`

后期参校：

- 中元 1；
- 下元 9。

与连续周期一致。

## 6. “直符 / 值符”名称边界

卷七直接正文以：

`直符`

为主名。

C15 旧字段题名写：

`明值符太乙所主術`

C64 固定：

- canonical：直符；
- 值符：legacy / title variant；
- 默认不静默 alias；
- 只有显式 compatibility mode 才映射为直符。

这避免把其他术数体系的“值符”概念无条件并入太乙直符。

## 7. 同宫灾应为什么暂不自动实现

卷七确有直接同宫断语，例如：

- 天乙与地乙；
- 天乙与直符；
- 天乙与四神 / 大游 / 小游；
- 地乙与直符 / 四神 / 大游 / 小游；
- 直符与四神 / 大游 / 小游。

但“两个 runtime 恰好算到同一宫”不等于调用方已经完成同一来源、同一时点、同一分野条件核验。

因此 C64 固定：

- `same_palace_omens_applied=False`
- `auto_same_palace_inference=False`

后续 C65 应把同宫对象作为显式输入，再逐条解释直接断语。

## 8. 旧字段迁移

C15 三项：

- 明天乙太乙所主術；
- 明地乙太乙所主術；
- 明值符太乙所主術。

现统一 action：

`use_c64_three_spirit_cycle_runtime`

但仍：

`migrate_whole=False`

原因是旧 flat 字段可能同时包含：

- 位置；
- 所主灾应；
- 同宫判断；
- 历史例。

C64 只替代位置周期部分。
