# 《太乙金镜式经》卷四军事十二法整理记录

## 结论

本次用户列出的十二条，应作为 **四库本《太乙金镜式经》卷四连续军事法** 单独建档，不应直接并入现有 C8 的 `volume5_strict` 来源层。

现有 C8 的目标是拆解旧 `junshi_zhanlue` 混合函数；本记录新增的是来源目录与 crosswalk。两者职责不同：

- C8：组合层边界，防止八占、三门五将、主客动静、将帅贤否互相覆盖。
- J4M：四库本《金镜》卷四十二法的来源顺序、标题异文、依赖与实现状态。

机器可读规则见 `rules/jinjing_v4_military.json`。

## 与 C8 的核对结果

### 已有但只覆盖部分语义

**J4M-01 / J4M-02 三门五将**

C8-L2 目前只归一化上游“三门具/不具、五将发/不发”事实，不重算公式。这一边界是正确的，但不能标记为 J4M 已实现。后续需要按《金镜》卷四单独实现直门、太乙/天目与门具关系，以及始击/文昌/主客大小将条件。

**J4M-04 推主客**

C8-L3 已正确保存两条角色规则：

- 陈兵原野：先动为客，后应为主。
- 安居之势：先动为主，后至为客。

但《金镜》正文还把三门、五将、阴阳和不和以及主客出入神一起放在本法中。C8 当前只实现“角色/动静”子层，故状态为 partial，不得称整条 J4M-04 已完成。

### 当前缺少独立层

J4M-03、05、06、07、08、09、10、11、12 当前均没有《金镜》卷四 source-specific canonical 实现。

尤其：

- **J4M-03 推主客相关法** 是五行相制/关法；不得并入 J4M-04 的先后动静。
- **J4M-05 推出师法** 以算十二/二十二/三十二、门具、将发、三吉门为条件；不得拿《统宗》卷五“人君出师略地”的兵车/甲士/步卒数量表代替。
- **J4M-06 推陈兵向背** 是按算数决定向背、阵型、旗色；不得拿旧项目卷十五“陈兵出乡”替代。
- **J4M-07 推制阵随地法** 与 **J4M-08 推随地制变** 相邻但不同：前者重阵形—五行—地势，后者重兵种/器械/训练随地应变。

## J4M-09 的来源冲突必须隔离

这里发现现库此前最容易再次混法的一处。

四库本《太乙金镜式经》卷四正文写作：

- 八、三、四：地内，助主。
- 九、二、七、六：天外，助客。
- 一宫在这段文字中没有列入地内组。

而《太乙统宗宝鉴》卷五同名术写作：

- 一、八、三、四：天内，助主。
- 九、二、七、六：天外，助客。

旧 `kentang2017/kintaiyi` 的 `ty_gong_dist` 采用的是后者 `[1,8,3,4]`。因此不能再把旧函数结果反写成《金镜》卷四 canonical。

本次规则表将两者保存为：

- `jinjing_siku_volume4` canonical：`[8,3,4]`
- `tongzong_volume5` source variant：`[1,8,3,4]`

一宫差异必须保留为来源异文/体系差异，待影印本进一步校勘，不自动“修正”为任一方。

## 旧参考实现只作线索

外部参考仓库 `kentang2017/kintaiyi` 可用于定位历史函数名，但不作为真源。此次核对发现：

- `threedoors` 只检查太乙所值八门，未体现《金镜》正文同时提到天目，不能直接升格。
- `fivegenerals` 把格局字符串与将居中五组合成结果，需重新按来源拆解。
- `wc_n_sj` 对应 J4M-03，但实现细节须重新核对“日计纳音”，不可直接搬运。
- `flybird_wl` 对应 J4M-11 的一部分，但只覆盖若干宫位分支，不能视为完整正文。
- 旧卷十五 `qibing_fubing` / `suidi_zhibian` 与《金镜》卷四存在内容重叠，但来源卷次不同，必须保留 source profile。

## 下一实现顺序

建议按依赖从低到高推进：

1. J4M-06 陈兵向背：纯算数查表，最适合先落成。
2. J4M-07 制阵随地：地形→阵型→五行，可独立实现。
3. J4M-09 天外地内：先做 source-specific profile，明确一宫差异。
4. J4M-05 出师：复用 J4M-01/02 的上游事实。
5. J4M-10 奇伏：依赖算数、天目、掩迫、地形。
6. J4M-03 主客相关：需先统一主/客目五行与日计纳音输入。
7. J4M-11/12：需设计“外部观测事实”模型，不能从盘内字段伪造风云飞鸟/云气观测。

- J4M-03 与 J4M-04 永不合并。
- J4M-07 与 J4M-08 永不合并。

## 第二批 source-specific runtime

继续新增三条，并保持不自动进入 C8 总胜负链。

### J4M-05 推出师法

运行入口：`chushi_fa(...)`。

正文条件拆为四栏：

- 算数须为 12 / 22 / 32；
- 三门具；
- 五将发；
- 实际出军取开、休、生三吉门。

实现上区分：

- `source_prerequisites_ready`：前三项是否成立；
- `exit_gate_valid`：所选出军门是否属三吉门；
- `deployment_ready`：四项齐备后才为 True。

因此“12/22/32 + 门具 + 将发”但尚未给出出军门时，只到 `ready_pending_gate`，不提前宣称已经完成出师条件。

本法继续明确禁止以《统宗》卷五“明人君出师略地术”的天子/诸侯/大夫兵额表替代。

### J4M-10 推奇伏法

运行入口：`qifu_fa(...)`。

正文信息不揉成一句断语，而分开保存：

- 奇兵比例：三成（百取三十、千取三百、万取三千）；
- 大煞位：天目所临之下；
- 12 / 22 / 32：伏兵时；
- 11 / 21 / 31：伏藏隐迹之时，藏山林沟涧；
- 伏兵取掩迫之时；
- 贼急：伏于要害。

对于不能整除十的任意现代输入兵数，只保存“三成”比例，不自行规定古法未说的取整方式。

### J4M-03 推主客相关法

运行入口：`zhuke_xiangguan(...)`，当前状态是 **partial source-specific**。

已经能够按正文与两个古例固定的核心是：

- 客目五行克主目五行 → 客关得主人 → 客胜；
- 主目五行克客目五行 → 主人关得客 → 主胜。

正文同时说“皆用日计纳音以决之”，但本段并没有继续说明日计纳音如何接入上述五行相制。现阶段：

- `day_nayin_element` 作为显式来源输入保留；
- 不用旧代码推断其角色；
- 不用纳音改写已由正文古例明确的相制关系；
- `fully_computable=False`，直到找到明确的纳音接法。

这样可避免把旧 `wc_n_sj` 的实现细节反向升级为《金镜》正文规则。


## 第三批 source-specific runtime

### J4M-01 推三门具不具

运行入口：

- `sanmen_jubu(...)`
- `zhimen_from_cycle_count(...)`

正文首先明确三门为开、休、生。现实现只宣称正文直接覆盖的组合：

- 太乙、天目分临开、生二门：两门不具；
- 太乙或天目临休门：三门不具。

对“两者同落开”“两者同落生”“只给太乙或只给天目”等本句未展开组合，返回 `not_defined_by_source_passage` / `not_computable`，不照搬旧 `threedoors` 只看太乙值门的简化逻辑。

同条正文另有直门算法：二百四十为一周，每三十移一门，上元甲子从开门开始，满三十年转休门。实现为 `zhimen_from_cycle_count()`，只接收已经换算好的 1-based 周期累计数，不擅自承担年/月/日/时历法换算。

州郡岁计直门吉凶独立保存：

- 开、休、生：大吉；
- 景：小吉；
- 死、惊、伤、杜：大凶。

门具事实与直门吉凶不得混成一个布尔值。

### J4M-02 推五将发不发

运行入口：`wujiang_fabu(...)`。

正文五将阻断条件拆为三栏：

- 始击将有无掩击；
- 文昌将有无囚迫；
- 主客大小将有无相关。

三者均无时，五将条件清。三门具/不具仍作为 J4M-01 上游事实独立输入。

输出继续分开：

- `five_generals_released`
- `three_doors_ready`
- `combined_ready`
- `deployment_allowed_by_doors`
- `engagement_allowed_by_generals`

并保存正文边界：“三门不具不可出兵，五将不发不可临战”。

旧 `fivegenerals` 中格局字符串、中五等混合判断不直接搬入本 profile。

### J4M-08 推随地制变

运行入口：`suidi_zhibian(...)`。

正文明确三项临战急务：

1. 士卒服习；
2. 随其地形；
3. 善用兵器。

现实现建立五类 terrain/arms 映射：

- 沟堑、山林、川泽、丘阜、草木之地：利步兵，原文“车骑三不当一”；
- 平陵、平原、广野：利车骑，原文“步兵十不当一”；
- 两阵相近、平地浅草、可前可后：利长戟，原文“剑楯三不当一”；
- 萑苇竹萧、草木蒙笼：利矛锤，原文“弓弩三不当一”；
- 平阳相远、山谷幽涧、仰高临下：利弓弩，原文“短兵百不当一”。

“三不当一/十不当一/百不当一”只保留为 `source_ratio_text`，不擅自翻译成现代战力倍数。

训练、器械、将知兵、君择将则作为 readiness/warning 层保存，不与 J4M-07 阵形五行合并，也不转成自动胜负分数。

## 第四批：外部观测规则

本批完成 J4M-11 与 J4M-12。两条都明确要求**外部观测事实**，不得从太乙盘内字段自动伪造风、云、飞鸟、云气。

### J4M-11 推太乙风云飞鸟助战法

运行入口：`fengyun_feiniao_zhuzhan(events)`。

输入为外部观测事件列表；每个事件至少可包含：

- `phenomenon`：风 / 云 / 飞鸟 / 风云 / 风云飞鸟
- `action`：冲格、迫击、击、扶、冲突、噪阵等
- `source_anchor`：太乙所在宫、主目、客目、主人形、太岁、太阴、月建等
- `target`：太乙、大将宫、主、客、主人阵、客阵
- `returning_wind`
- `birds_circling`
- `flag_broken`
- `crowd_noisy`

正文明确事件逐条实现：

- 太乙所在宫风云飞鸟冲格迫击太乙 → 大败之兆
- 迫击大将宫 → 主败
- 从主目上去击客 → 客败
- 从客目上击主 → 主败
- 从主人形上来 → 客败
- 从太岁 / 太阴 / 月建上来击主人 → 主败
- 从太岁 / 太阴 / 月建上来击客 → 客败
- 扶主人阵 → 主胜
- 扶客阵 → 客胜
- 回风起伏 + 飞鸟旋转阵中 + 旗折 → 大败之兆
- 风云冲突主人阵 → 主败
- 风云冲突客阵 → 客败

“众来噪阵”在本句中被提及，但没有单独明示其独立胜负结果；实现只记录该观测并返回未匹配，不根据旧代码或近似语义自行补断。

无任何外部观测时返回 `not_computable`。

### J4M-12 推阵有风云气定胜负

运行入口：`yunqi_dingshengfu(...)`。

本法拆成四层：

1. 云气所覆阵的方位 × 云气颜色基础表
2. 日干加重
3. 云气聚散、动静修正
4. 云气所临大将 / 参将修正

基础表完全按卷四正文保存，不以一般五行生克补缺项。

**北方阵：**

- 黑：大胜；壬癸日弥佳
- 白：欲罢阵求和
- 青：将宽缓，急击则平
- 红：客胜
- 黄：大败；壬癸日弥恶

**南方阵：**

- 赤：大胜；丙丁日弥佳
- 青：欲罢阵求解
- 黄：将迟钝，急击则平
- 白：失利
- 黑：大败；丙丁日弥恶

**西方阵：**

- 白：大胜；庚辛日弥佳
- 黄：欲求解
- 黑：将宽缓，急击平
- 青：败
- 赤：大败；庚辛日弥恶

**东方阵：**

- 青：大胜；甲乙日弥佳
- 黑：欲求和
- 赤：将迟钝，然不可击
- 黄：大败；甲乙日弥恶
- 白：正文未列，保持 `not_defined_by_source_passage`

云气形态层：

- 胜气动利：大胜
- 虽得胜气，但断续不次或南北溃乱：反败
- 败气断续溃乱：不至全恶
- “败云气坚实动大利”保留为原文修正注，不擅自翻成一个现代确定胜负规则

将位层：

- 胜云气在大将上：大胜
- 胜云气在参将上：参将胜
- 败云气在大将/参将上：原文只说“反此”，实现保留该原文关系，不扩写未明细节

若完全无云气，返回原文层级“无战或复相匀”，不强判胜负。
