# C70 《太乙统宗宝鉴》卷六文昌九宫 / 九星 source-specific runtime

日期：2026-10-05

## 1. 为什么建立 C70

旧项目顶层字段：

`文昌九星`

原实现 `config.wenchang_nine_stars` 自己明确标注来源为：

`《太乙统宗宝鉴》卷六“明文昌九星行九宫所主分野术”`

因此这个 legacy 字段不能继续因为项目另把《太乙紫庭秘诀》附篇设为主来源目标，就整体标成“来源未知”。

C70 将两件事拆开：

- 统宗卷六：已有可直接校读正文，可建立 source-specific runtime；
- 紫庭附篇：目录已证“附太乙文昌九星值宫术”，正文仍未取得，继续 primary text pending。

两者绝不静默合并。

## 2. C70 选择的统宗见证

本 runtime 只选择：

- 《太乙统宗宝鉴》卷六；
- NGJ witness：`NGJ892411999009267118912`；
- 题：`明文昌九宫所主分野术`。

该见证正文连续一致地写出：

- 每星三十年行一宫；
- 大周2700；
- 小周270；
- 宫率30；
- 命起一宫文昌；
- 顺行九宫。

因此 C70 的 30 年只对这个 source profile 宣称成立，不宣布为跨来源统一 canonical。

## 5. 周期异文不乱合

C34 已记录：

### 统宗 CADAL

同一电子见证内部：

- 叙述句：10年一宫；
- 推法：30年一宫；
- 小周270；
- 大周2700。

固定为 internal conflict。

### 三才世纬

外部直接见证支持30年一宫，但当前电子转录的大周数字另有270等异读。

因此：

- C70 可运行的是 NGJ source profile；
- C34 的 cross-source `canonical_selected=None` 保持不变；
- 紫庭附篇不能被 C70 反填。

## 6. 年干落宫

正文说：

`命加所求年干建禄之宫`

NGJ 表与紧随其后的例子支持：

- 甲 → 艮 / 青州；
- 乙 → 震 / 徐州；
- 丙 → 巽 / 扬州；
- 丁 → 离 / 荆州；
- 戊己 → 中 / 豫州；
- 庚 → 坤 / 梁益州；
- 辛 → 兑 / 雍州；
- 壬 → 乾 / 冀州；
- 癸 → 坎 / 兖州。

原例：

- 甲辰年玄凤直事，第11年在青州；
- 次年乙巳在徐。

这说明：

- “哪个星直事”由270/30周期决定；
- “该直事星当年落何宫 / 分野”由年干层决定。

C70 明确把两层分开。

## 7. 旧实现错误隔离

旧 `config.wenchang_nine_stars` 现进入 C60 quarantine。

已确认问题：

1. 星名表混入：
   - 文曲；
   - 昭摇；
   - 立华；
   - 等非当前 NGJ 读法。
2. 年干表：
   - 丁旧写9 / 巽，直接表应2 / 离；
   - 壬旧写5 / 中，直接表应1 / 乾。
3. 旧“九星分布”循环虽然计算 `gong`，但该变量未用于输出键；
   实际仍返回固定星宫表，不能证明是正文要求的动态分布。
4. 旧实现没有保存：
   - 统宗 CADAL 的10/30内部冲突；
   - 紫庭附篇正文 pending。

因此：

`canonical_equivalent=False`

replacement：

`C70-TONGZONG-WENCHANG-NINE-STARS`

## 8. C70 不做的事

C70 当前不实现“其余八星完整动态重排”。

原因：

当前直接正文足以核：

- 直事星；
- 入星年；
- 直事星按年干所临宫 / 分野。

但不能用旧代码的错误循环反推其余八星完整动态分布。

固定：

- `full_dynamic_distribution=None`
- `dynamic_distribution_boundary.supported=False`
